# OpenCodex Lite 架构

## 产品与实现范围

Lite 是 Windows 本机 AI 聚合网关。Python 后端提供协议入口、管理 API、网页资源和进程管理；React 控制台使用 Node.js 与 pnpm 构建。Service Desk 仅提供网页入口。

当前选定的上游是 OpenAI API、ChatGPT 登录、DeepSeek API、MiMo API、OpenCode Zen 和 OpenCode Go；自动接入客户端为 Codex 和 DSH。API 允许独立渠道，订阅按渠道单账号管理。通用协议能力服务于这些连接，不以模型所属品牌决定是否加载厂商认证。

`backend` 是 Python 顶层包，CLI 与 Windows 服务均从 `backend.runtime` 启动。旧 `backend/ocx`、TS `backend/src` 和 npm `backend/bin` 已移除；原实现通过 Git 历史参考（替换前提交 `8c04a0cd4`）。前端契约位于 `frontend/src/contracts`。当前全量架构整理仍在实施和验收中，模块已迁移与产品已验收是两种状态。

## 责任与依赖

| 模块                 | 所有权                                                         |
| -------------------- | -------------------------------------------------------------- |
| app.py / services.py | HTTP 应用组装、领域服务接线、资源关闭和后台任务                |
| api                  | HTTP 输入输出、管理会话、错误映射及响应生命周期                |
| application          | 渠道、目录、设置等管理用例，公开 DTO、配置提交与客户端应用结果 |
| configuration        | 配置结构、版本转换和持久化；凭据记录与公开响应分开             |
| providers / auth     | 服务定义、用户渠道、端点声明、认证和账号生命周期               |
| catalog              | 发现快照、元数据、用户覆盖、生效模型及通用投影、后台刷新       |
| requests.py          | 逻辑请求、实际发送、协议与取消信号等中立事实类型               |
| gateway              | 路由和执行流程、逻辑请求、实际发送、重试及取消                 |
| protocols            | 协议编解码、流式事件转换和原生直通                             |
| integrations         | Codex／DSH 接入适配、配置投影、同步协调、状态与恢复            |
| policies             | 模型控制、压缩、辅助调用和工作流限制                           |
| telemetry            | 实际发送记录、用量、定价和诊断                                 |
| runtime              | CLI 入口、进程生命周期、服务操作、Windows 计划任务与监督进程   |
| platform             | 跨模块使用的 Windows 文件锁等宿主原语                          |

管理路由将 HTTP 请求交给 `application` 的业务用例或集成服务；权威校验、配置提交和副作用由后端完成。`SettingsService` 负责配置事务，模型选择、子代理、请求策略和辅助设置的用例分别组织；保存配置与应用到客户端分别返回结果，避免把客户端同步失败误报成配置未保存。前端负责输入反馈、交互状态与展示，通过管理契约访问后端，不导入后端实现。

生成入口调用 `gateway`。协议转换不管理账号或客户端文件；供应商声明与认证位于接入边界；通用模型投影由 `catalog` 提供，DSH 和网关策略不再依赖 Codex 的目录方法。`services.py` 注入这些依赖，`requests.py` 为执行和观测共享请求事实，避免观测层反向依赖执行器实现。

## 配置与契约

新配置版本为 2，区分渠道 ID、服务 ID、协议和认证方式。渠道 ID 与模型原始 ID 保持稳定；显示名称、别名和客户端选择器编码不改变实际身份。无冲突的既有选择器保持不变；原生模型 ID 折叠后发生冲突时，目录为各模型提供可逆的明确选择器，旧歧义名称继续拒绝。冲突历史随配置保存，模型移除或重启后不会把旧名称重新绑定到另一模型。路由解析之后，默认模型、备用线路、续聊和内部辅助请求都传递原生身份，不再次解释外部名称。

协议选择保留显式单模型覆盖优先于渠道默认的语义。服务定义提供缺省端点与已确认的服务规则；用户显式覆盖优先，服务声明只适用于匹配的连接。模型发现与生成端点分别声明，避免从 Messages 路径推导模型目录地址。

发现快照、元数据补充和用户覆盖分别保存。生效值保留全局默认、渠道覆盖、单模型覆盖的层次；空集合、显式关闭与继承分别解释。成功获取完整目录替换发现名单，未知新模型不依赖静态名单准入。普通读取使用持久化快照，成功结果按每日周期刷新，包括有效的空目录；失败保留最后成功目录，并从 1 分钟开始指数退避重试，上限 1 小时，失败次数随快照保存。连接身份变化立即重新发现，显式刷新绕过退避。并发刷新共享目录及同次客户端应用结果，目录未变化不重复同步客户端。

渠道管理与首页运行状态使用独立公开 DTO。凭据密文、自定义认证头和迁移剩余数据不成为响应字段。凭据编辑区分保持、替换、环境变量引用和清除；登录状态未确认与明确缺少凭据是不同状态。当前仍有设置和客户端接口使用字典结构与用例校验，不能把已导出的 Schema 视作全部管理 API 的完整契约。

配置升级先生成独立候选结果，保留原始输入。已识别字段转换到新模型；尚未映射的字段保留在迁移剩余结果中。剩余字段清零只证明转换覆盖完整，实际激活仍需对应执行器、客户端适配与管理 API 完成接线。

## 控制台职责

控制台只连接当前本机源。`api.ts` 负责会话引导、CSRF、并发续期与调用方取消隔离；不再区分远程控制面、机器控制面或管理员令牌。管理 API 的字段解码位于相应领域资源边界，页面不把合法的 `null` 当作网络断连。后端返回的配置保存结果与客户端应用结果分别呈现。

入口先声明设计体系的 CSS 层顺序，再加载外壳和首页，避免组件导入顺序改变样式优先级。其余八个业务页面在首次进入时加载，公共控件由构建器按实际依赖共享，不配置按包大小机械切分的规则。页面模块下载期间保留导航和目标页标题、显示占位；再次进入复用模块。模块下载失败可重新加载文档，普通渲染异常仍在原页面边界内重试。

英文词典定义文案键，其余十种语言分别按需加载，缺失译文在词典加载边界统一回退到英文，不再由页面内的中英文分支或跨语言补充表提供文案。新增 Lite 文案已补充简体与台湾繁体中文；其他语言复用已有对应翻译，尚未补齐的新增文案使用英文。首次显示等待首选语言，切换期间保留当前界面，以最后一次选择为准；失败保留原偏好并提供可关闭提示。语言包等待期间的确认框继续响应导航和取消。

页面按首页、渠道、模型、客户端、子代理、用量与日志、网关设置组织。首页共用一个 overview 资源承载运行状态、自动启动和诊断；轮询保持进程状态实时，仅缓存计划任务注册信息最多 5 分钟，诊断错误最多 1 分钟。服务操作回执、偏好或任务定义文件变化使缓存失效，显式刷新直接重查注册。渠道领域管理目录、渠道编辑及单账号生命周期；客户端领域分别组织 Codex 与 DSH 的预览、应用和恢复。领域资源负责请求和刷新，组件负责编辑状态与展示，不以大 hook 替代业务拆分。

`design/theme.css` 提供设计值，`design/controls.css` 定义基础控件，`components/settings` 统一面板和设置行，页面结构样式按业务归属组织。React 按钮与命令式对话框共用按钮样式定义，不再通过旧 `.btn` 或覆盖桥接维持另一套控件。帮助浮层补充必要信息，加载和后台刷新保留页面结构；Routing 与密钥速率限制以待实现状态保留。视觉语言、构图和渲染验收原则见 [前端设计](frontend-design.md)。

## 请求执行与客户端接入

Dispatcher 负责选择目标、fallback 和请求级策略；Executor 执行单个目标及 OAuth 刷新重试；PhysicalAttempt 持有每次真实发送及其结算。内部搜索、视觉和压缩沿同一执行链调用，继承父任务、取消和用量归属，无需绕回本机 HTTP。原生搜索不提供可靠 token 用量，不计入 token 预算，但仍受请求次数、发送节奏等限制并记录发送事实。HTTP 适配层负责请求解压、断连和响应生命周期，协议层负责原生直通与跨协议转换。

Codex 原生裸模型名的兼容路由由 `integrations/request_routing.py` 处理，再将明确的选择器交给通用路由。该规则只适用于识别到的 Codex 客户端及 Responses 入口，显式渠道和用户别名不被覆盖。客户端角色文件由 Codex adapter 读取为 fallback 快照，启动、同步、状态读取及后台观察更新快照，请求路径不读取客户端文件。

`IntegrationCoordinator` 在启动和生效目录／设置变化后分别协调 Codex、DSH，并保留各自结果。Codex 沿显式启用意图恢复或同步；DSH 只自动更新仍由 Lite 管理且未被外部编辑的 provider 片段。一个客户端失败不阻止另一个执行，冲突进入待处理状态，关闭的接入不会因目录刷新而重新启用。预览、显式应用、禁用和恢复仍由各客户端 adapter 实现。

生成发送的用量在物理请求边界归一化，仅在终态及计数完整性满足条件时结算；未知、估算或不完整用量不当作零。上游传输中断与下游断连分别归因。缓冲成功体、错误体和 SSE 聚合体按解压后的 16 MiB 限制，SSE 单帧另有限制，正常流不设累计长度上限。原生流中断保留已经发送的字节，不向半截协议帧追加合成错误事件。

客户端公共文件读写位于 `integrations/files.py`，Codex TOML、目录、缓存和原生设置各有所有者。Codex 恢复依据操作日志撤回已管理字段并保留无关编辑；DSH 普通禁用只撤销 provider 片段，快照恢复则保留其显式预览与漂移确认语义。受管片段由 Lite 生成，其内部注释可随替换或移除丢弃；片段外的独立注释保留，空白格式可能被 YAML 序列化规范化。操作日志保存修改前全文。Codex 进程新鲜度检测及显式重启位于 `integrations/codex_process.py`，不属于 HTTP 路由实现。

## 运行管理与产品里程碑

`ocx start` 和 `ocx restart` 在当前终端前台运行，默认端口为 10100，显式端口优先，未指定时沿用运行记录中的端口。后台运行统一使用 `ocx service …`。CLI 只解析命令和展示结果；`runtime/process.py` 管理进程，`runtime/service.py` 编排服务操作和失败恢复，`scheduler.py` 适配 Windows 计划任务，`supervisor.py` 负责后台监督。

网页服务操作和 CLI 共用操作计划。会停止当前 HTTP 进程的操作由分离进程继续执行；服务移除按停止网关、等待监督进程和计划任务结束、移除注册的顺序进行。修复服务保留原自动启动启用状态，失败时尝试恢复原注册和运行状态。Service Desk 仅打开网页，不承担这些生命周期操作。

首页通过 `/api/overview` 读取运行状态、服务状态、渠道计数与产品里程碑。首次成功请求记录在 `configuration.sqlite3` 的独立 `milestones` 表中，与最近七天统计和日志保留周期解耦；启动时仅从可确认的成功生成记录补入。额度、目录、计数、压缩、失败及中断请求不计入。引导完成后消失，自动启动不作为完成条件。

## 整理顺序与完成条件

1. 契约与数据语义：核对空值、继承与显式覆盖、权威校验、错误分类及持久化里程碑。
2. 后端职责与依赖：管理用例从 HTTP 层分离，通用模型与请求事实归属明确，供应商及客户端差异留在接入边界。
3. 执行与运行生命周期：核对流式、取消、重试、辅助调用结算，以及前台／服务操作和客户端恢复。
4. 前端产品结构：统一基础控件、设计值、页面容器、设置行、帮助与加载状态，落实精简后的入口和二级导航。
5. 完整验收：工程检查、隔离业务验证与实际页面验证分别记录，再核对日常实例、自动启动和当前客户端配置。

这些是连续实施中的过程节点。旧源码删除、模块拆分或构建成功不能代替业务链验收；读取、保存、生效、失败和恢复的检查结果及尚未执行的真实场景分别记录在迁移文档中。

## 配置与契约工具

在仓库环境中执行 `python -m backend.configuration <旧配置路径>` 可预览转换摘要；加 `--output <新目录>` 默认只生成脱敏转换报告，记录字段覆盖、渠道标识和未映射字段路径，不导出这些字段的值；报告仍含用户标识符和路径，不等于可公开分享的匿名材料。加 `--include-sensitive` 才额外生成完整配置、凭据记录和未映射值，这些文件可能包含认证头与旧密钥，应作为私有迁移材料保存。默认报告不是可激活配置。输出目录必须尚不存在，生成结果不会自动启用。退出码 0 表示字段转换完整，1 表示存在未映射字段，2 表示转换失败。

`python -m backend.api.schema --output <文件路径>` 导出当前登记的管理 DTO，结果版本为 2。定义位于 `backend/application/contracts.py` 和 `runtime_contracts.py`：`ChannelList` 包含渠道列表，`ChannelDetail` 包含可编辑渠道与凭据状态，`SaveChannel` 将配置和凭据操作分开表达；`Overview`、`StartupHealth` 描述首页及服务状态。导出工具不启动网关，也不自动生成前端类型；前后端仍需对实际响应核验字段名称、必填性和可空性。

用量与日志中的“存储”页面管理 Lite 自身数据；旧文件分类用于识别和保留敏感遗留材料，不代表重新支持退役功能。`/api/provider-import` 保留为显式的原版 API 渠道导入预览与应用入口，不自动激活旧配置、不导入退役 OAuth，目前没有网页入口。

## 当前实现与验证

主要模块迁移已经落地；后续复核发现并修复了用量结算、失败归因、目录刷新、应用回执、认证状态和前端样式等跨模块问题，不能用模块迁移完成代替功能验收。本文描述当前职责分工，迁移范围、已执行验收及未验证场景见 [MIGRATION.md](../MIGRATION.md)。

日常实例已采用版本 2 配置和 Python 模块入口，并在本轮重启加载整理后的实现。配置与私有凭据记录仍在同一 SQLite 事务内提交，首次激活保留旧 `config.json`。退役 OAuth 在转换报告中标记，不自动激活；已有 v2 退役渠道保持可见和可移除，不占 ChatGPT 接入槽。旧入站密钥无法映射的字段继续阻断激活并供核对，不自动重新启用旧密钥。自动启动偏好及当前 Codex 配置、登录文件的校验值保持不变。
