# OpenCodex Lite 前端设计

OpenCodex Lite 是日常使用的个人 AI 网关控制台。界面首先回答网关是否正常、当前操作作用于谁、操作是否完成，再提供配置与诊断细节。视觉设计和业务行为共同构成产品；重构必须保留有用的色彩、层次与交互反馈。

## 视觉语言

浅色使用白色与中性灰内容面，深色使用黑色与中性灰内容面。选中、焦点和主要操作使用黑白灰对比，不使用紫色配色或装饰性渐变。成功、警告和失败保留语义色；供应商和客户端保留品牌标识。

页面标题为 26px，区域标题为 15–16px，正文与控件为 13–14px，辅助状态为 12px。沿用已打包的 Geist 字体及系统回退，模型标识、路径和地址使用等宽字体。信息层级同时依靠位置、字重和间距，不能只靠灰度区分。数字保持等宽，长标识允许换行。

主按钮使用纯色黑白对比及悬停、按压反馈；次要操作使用描边或文字按钮。普通控件高 36px，小控件高 30px，文字与图标共同居中。危险操作与日常主要操作分离。选中状态同时使用底色和形状，不能只用颜色表达。

## 构图与交互

外壳统一页面宽度、标题位置和边距。业务页面按任务组织内部构图：渠道采用列表与详情，连接和目录相邻，账号与额度集中，诊断按需展开；首页优先展示运行与自动启动。数据密集的模型和日志页面保留适合扫描的行结构，不强行改成卡片墙。

相关信息使用 8–16px 的局部间距，独立区域使用更大的间距。一个业务分组只需要一个主要内容面，避免多层卡片、描边和阴影重复表达同一边界。窄窗下根据内容宽度收成单列，操作可以换行，技术字段不能撑破页面。

帮助浮层只补充操作所需的解释。后台刷新保留已有内容，按钮表达进行中状态；初载占位应与实际行的高度相符。动效用于反馈选择、按压与刷新，并响应减少动态效果的系统设置。

本机文件位置以用途和文件名呈现，通过“打开文件夹”完成定位，不在普通页面展开绝对路径。文件位置行由共享组件负责显示，后端把固定位置标识映射到本机路径。账号页只在用户准备登录或更换账号时显示登录方式；渠道移除属于编辑操作区，与取消、保存分组，不独立悬挂在详情页外。

## 实现与验收

`design/theme.css` 持有设计值，`design/controls.css` 和共享 React 控件负责交互外观，`components/settings` 负责设置面板与行。页面自己的布局由业务目录持有。调整外观应修改所属组件，不增加旧样式桥接层。

验收必须查看实际渲染：中英文、浅深主题、常见桌面宽度及窄窗口；检查初载、刷新、页面切换、帮助展开、长字段和错误状态。格式、lint、类型和构建检查只证明工程约束通过，不能替代视觉判断。新增功能和后续重构应沿用这些原则，并重新检查受影响页面。
